# admin 权限目录全量功能扫描

## 验收范围

本轮以测试环境 `admin` 的真实菜单和权限为边界，不以源码清单代替运行验收。
扫描先读取参考菜单、当前用户菜单、角色权限和用户权限，再逐一打开全部可导航入口。
每个页面均记录导航状态、空白页、可见错误、未翻译键、浏览器 console、
XHR/fetch/script/stylesheet 失败和可见控件。

- API 入口：`http://10.11.100.17:18080`
- 浏览器入口：`http://39.164.227.152:18080`
- 数据库：PostgreSQL
- 参考目录节点：652
- admin 可见节点：533
- 可导航页面：398
- 权限接口核对：533/533 PASS，按钮权限缺口 0
- 页面最终结果：185 PASS、42 WARN、171 FAIL

`PASS` 要求页面非空、没有可见系统错误、没有关键网络/console/page error。
`WARN` 表示页面可操作，但存在未翻译键或已知参数告警。HTTP 200 的空白页仍为 `FAIL`。

## 警告明细

42 个 WARN 中，24 个页面仍有 `ec.common.tableNo`、`PATROL.custom...`
等未翻译键；18 个页面触发旧组件的“请将参数放在数组里”console 告警。
这些页面当前可打开，不能等同于交互与业务动作全部验收完成。

## 本轮修复

1. 补齐 admin 目录中 4 个缺失操作权限，复验角色和用户权限为 533/533。
2. 修复 OEE/工厂树 PostgreSQL 层级字段兼容，树接口恢复 200。
3. 增加 PostgreSQL legacy OID 与 bigint 的兼容运算符，WTS 正常封票链路恢复。
4. 补齐缺失 i18n/CSS 静态资源兼容，减少页面原始键和资源失败。
5. 消除消息中心旧 notification 五服务与 `msgmanagement` 的重复注册；默认编排只保留
   `msgmanagement`，旧服务进入 `legacy-notification` profile。
6. 将缺失的 `NoticeProtocolMapper` 暴露到合并服务实际扫描路径。消息任务接口连续
   10 次返回 200，最终耗时 38-150 ms；消息中心真实页面复验 PASS。
7. 补齐 PostgreSQL `mobile_device_token` 运行表，消除移动通知的缺表异常。通知分发仍有
   独立失败，未把表结构修复扩大为渠道可用结论。

## 真实业务动作

全量目录扫描不会对 398 页逐一执行删除或审批等破坏性动作。为验证按钮权限和真实落库，
本轮选择跨域代表链路执行唯一 marker，并直接查询 PostgreSQL：

接口 200 不是单独通过依据；以上结论同时要求页面/API、业务状态和 PostgreSQL 查询一致。

`send_status` 均为 0。服务返回 `all fail`，移动通知还触发旧代码空指针，因此消息中心
列表页的 PASS 不能替代通知送达验收。

## 结论

admin 的权限配置层已经完整，但当前产品目录不能判定为“全部可用”。
核心生产、质量、仓储、追溯、组织、权限、巡检和 WTS 代表链路已经有真实落库证据；
设备管理、计量、工具和若干旧扩展包仍有 169 个空白入口，是标准产品分支冻结前的主要缺口。
通知中心列表和查询已恢复，但 WTS 实时站内信/移动通知仍未送达，也必须在冻结清单中保持
`FAIL`。
建议先把这些入口从标准版目录隐藏，或按 EAM -> Measure -> TOOL 的优先级补齐运行包，
不要让不可用菜单继续暴露给正式用户。
