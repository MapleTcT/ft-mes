## Acceptance Rule

Phase 0/1 PASS requires real JetLinks events or an approved faithful replay, observable Kafka/Flink
processing, a real BPI page operation, API evidence, PostgreSQL verification, and cleanup/replay proof.
HTTP 200, mock-only tests, static code inspection, or a rendered menu are insufficient.

## Affected Pages/Routes

- `/bpi/realtime` — current production line, active/candidate batch, confidence and data health.
- `/bpi/reviews` — candidate, conflict, late evidence and forced-close review queue.
- `/bpi/batches` — batch filtering, cursor pagination and status visibility.
- `/bpi/batches/{id}` — evidence, curves, state events, balance, QA/WMS and audit.
- `/bpi/rules` — rule list, draft/version state, approval and publication.
- `/bpi/rules/{id}/simulation` — historical replay comparison and checksum.
- `/bpi/topology` — process nodes, edges, locality groups, signal and calibration binding.
- `/bpi/data-quality` — gap, bad quality, clock drift, rejected point and shared-meter issues.
- `/bpi/corrections` — amount/time/boundary/genealogy correction and approval.
- `/bpi/datasets` — definition, snapshot generation, exclusion and lineage.

## Key Interactions to Verify

- Open a line with no production and distinguish idle from disconnected or stale.
- Receive a low-confidence candidate and confirm it once from two concurrent browser sessions.
- Receive a high-confidence candidate and verify automatic ACTIVE plus complete evidence.
- Reject a false candidate and verify the same replay does not recreate it without a rule/context change.
- Suspend an ACTIVE batch when WOM context expires, then reconcile after WOM returns.
- Force-close with reason and approval; verify correction/audit rather than row overwrite.
- Publish a rule only after a successful simulation with the same rule/topology/calibration versions.
- Open a batch while raw curves are unavailable and verify business facts remain usable.
- Resolve a late-evidence AMENDING case and verify it returns to RECONCILING.
- Link final QCS results and verify WAIT_QA only releases after all required inspections accept.
- Trigger WMS completion inbound once and verify retries return the same document.
- Generate a dataset snapshot and verify prediction time, exclusions, manifest and checksum.

## Edge Cases

- One invalid PointValue inside an otherwise valid envelope: valid points continue; only bad point rejects.
- Missing deviceId/eventTime at envelope level: whole envelope quarantines with visible incident.
- Duplicate sourceEpoch+sequence and duplicate candidate key across Flink restart.
- Same eventId with different payload checksum: quarantine as corruption, never overwrite.
- Out-of-order data inside allowed lateness, beyond allowed lateness, and after WAIT_QA.
- Event-time watermark stalls because one gateway is idle.
- Unknown unit, runtime unit change, calibration out-of-range and missing material curve.
- Flow gap below interpolation threshold and above threshold; estimated fraction exceeds cap.
- Shared meter without allocation, allocation sum below/above physical total, circular allocation dependency.
- Pump state flaps around start threshold; flow oscillates around hysteresis boundary.
- Production order changes while valves and flow remain active.
- Source/target tank switches at the same time as an order switch.
- Two batches attempt the same batch number or WMS idempotency key.
- Two users submit stale revisions or double-click confirmation/force-close.
- Adapter token expired, role revoked, forged tenant header and cross-tenant object ID.
- Kafka unavailable until exporter spool reaches 70%, 85%, 95% and full.
- PostgreSQL unavailable between state transition and outbox publish.
- QCS accepts some required tests and rejects or delays others.
- WMS commits but reply times out; retry must query by idempotency key.
- Iceberg/MinIO unavailable during snapshot generation.
- Dataset contains a feature after prediction_time or random-row split leakage.
- Empty list, one result, 10,000 results, cursor page changes during live updates.
- Browser navigation, refresh, offline mode and deployment during an async command.

## Critical Paths

### CP1: Telemetry To Shadow Candidate

```text
JetLinks property report
  -> exporter validation/batching/spool
  -> Protobuf/Apicurio/Kafka
  -> Flink event time/unit/quality/totalizer/rule
  -> deterministic candidate
  -> BPI inbox/state/PostgreSQL
  -> real-time page and review queue
```

Evidence: source event IDs, Kafka offsets, Flink checkpoint, candidate key, BPI rows and page screenshot.

### CP2: Restart And Replay

```text
ACTIVE stream -> kill exporter/broker/TaskManager/BPI -> recover -> replay
             -> identical fixed-scale total -> one candidate -> one state history
```

Evidence: before/after checksum, zero duplicate business rows, spool/lag recovery and no silent gap.

### CP3: Candidate Review And Correction

```text
CANDIDATE -> confirm -> ACTIVE -> late evidence -> AMENDING
          -> approved correction -> RECONCILING -> WAIT_QA
```

Evidence: optimistic revision, correction before/after, approval, audit log and PostgreSQL marker.

### CP4: QA To WMS

```text
WAIT_QA -> all required QCS ACCEPT -> RELEASED + outbox in one transaction
        -> WmsInboundCommand -> same document on retry -> INBOUNDED
```

Evidence: QCS references, BPI state/outbox, WMS document/stock transactions and timeout-retry proof.

### CP5: Training Dataset

```text
released reviewed batches -> point-in-time features + later labels
                         -> exclusions/leakage gate -> Iceberg manifest
                         -> MLflow dataset/run lineage
```

Evidence: immutable manifest/checksum, feature cutoff, label availability, code/rule/topology versions.

## Load And Chaos Gates

- 25k points/s for 24h: no unexplained loss, stable checkpoint and bounded lag.
- 50k points/s sustained: p95 real-time state under 5s and candidate under 10s.
- 250k points/s for 60s: no OOM, spool/backpressure policy activates as designed.
- One Kafka broker loss: no unavailable partition at replication factor 3/min ISR 2.
- TaskManager restart: same event set produces identical fixed-scale accumulators.
- PostgreSQL restart: inbox/outbox resumes without missing or duplicate transitions.
- MinIO outage: online batches continue; snapshots fail visibly and retry safely.

## Required Test Assets

- Versioned synthetic plant event generator with deterministic seed and golden checksums.
- Anonymized one-line replay manifest with approved event/time/quality semantics.
- PostgreSQL marker queries and cleanup statements for every state-changing E2E case.
- Kafka/Flink fault-injection scripts and before/after metric snapshots.
- Playwright page/API/network/console evidence collector following repository acceptance rules.
- Contract compatibility fixtures for previous Protobuf versions and invalid changes.
