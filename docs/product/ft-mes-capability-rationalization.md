# FT MES 功能裁剪与行业分支策略

> 文档状态：`PRODUCT_RATIONALIZATION_PROPOSAL`
>
> 生成日期：2026-08-10
>
> 代码基线：`c1233a3c2319ed8ff26c974c9f297d50cb673744`
>
> 执行边界：本文件定义产品减法，不直接删除菜单、源码、数据库表、镜像或部署服务。真实下线必须经过
> 使用观测、依赖分析、回归、备份和回滚门禁。

## 1. 为什么现在必须做减法

当前仓库同时承载 ADP/BAP 平台、多个年代的 MES 业务包、恢复前端、运行 JAR、PostgreSQL 兼容层、
新建 BPI 和大量实施工具。它们是恢复资产集合，不等于一个用户应该看到的产品。

本轮静态盘点与历史验收揭示了四个结构性问题：

1. 当前 Compose 有 80 个服务，其中 28 个平台运行服务、20 个业务运行服务、21 个支持服务和
   11 个基础设施服务；数量反映历史交付方式，不是目标架构。
2. 独立业务源码仓包含约 13GB、41 个版本目录、18,301 个 Java 文件和约 169 万行 Java；同一业务域
   存在多版本并存，不能全部作为标准版继续维护。
3. admin 目录扫描的 398 个可导航页面只有 185 个 `PASS`、42 个 `WARN`、171 个 `FAIL`；其中
   169 个失败为 HTTP 200 空白页，集中在旧 EAM、检维修、备件、计量、工具和停机包。
4. 页面存在不代表业务完成。部分模块只有菜单、查询或按钮可见证据，没有真实写动作、状态机、
   PostgreSQL 落库和异常路径验收。

因此，裁剪目标不是把 398 个页面逐个修亮，而是用最小产品承诺覆盖最重要的生产事实闭环。

## 2. 裁剪原则

### 2.1 产品判断顺序

每项能力按以下顺序决策：

1. 是否直接支撑“制造指令到批次追溯”的核心闭环。
2. 是否具有清晰用户、业务对象、状态机和最终业务结果。
3. 是否已有真实页面、API、PostgreSQL 和异常路径证据。
4. 是否能与相邻能力合并为任务型工作台。
5. 是否只对某个行业、法规或实施团队有价值。
6. 是否存在完整源码、依赖、迁移和可持续测试路径。

历史包已存在、菜单已配置、接口返回 200、数据库有表，都不能单独构成保留理由。

### 2.2 六类处置

| 决策 | 含义 | 默认菜单 | 代码处置 |
| --- | --- | --- | --- |
| `KEEP_STANDARD` | 标准产品直接承诺 | 显示 | 进入标准回归和发布门禁 |
| `MERGE_INTO_STANDARD` | 业务有价值，但入口过散 | 合并后显示 | 保留能力，重做信息架构/API 边界 |
| `INDUSTRY_PACK` | 特定行业或法规能力 | 标准版隐藏 | 独立模块、迁移、profile 和验收 |
| `INTERNAL_CONSOLE` | 实施、开发或运维工具 | 业务角色隐藏 | 只授权实施管理员，不计产品页面 |
| `HIDE_UNTIL_READY` | 方向可能有价值，但当前不具备交付条件 | 隐藏 | 保留隔离资产，补齐门禁后再评审 |
| `RETIRE_AFTER_OBSERVATION` | 重复、过时或无可靠使用价值 | 隐藏 | 先观测和导出，后续版本物理退役 |

## 3. 标准产品边界

本文件只回答实现层能力应保留、合并、隐藏还是退役。共享底座、领域产品、硬依赖、成熟度和商业组合的
产品层权威定义见
[FT 制造软件模块化产品矩阵](ft-mes-modular-product-portfolio.md)。同一个产品可以引用多项能力，
同一商业组合也可以装配多个领域产品；不得把本文件的 45 项能力重新解释成 45 个产品。

### 3.1 标准版必须闭合

```text
制造指令 -> 工序执行 -> 投料/退料/报工 -> 请检 -> 质量判定与处置
        -> 完工入库 -> 批次追溯
```

标准版一级菜单固定为：工作台、生产执行、质量管理、物料库存、批次追溯、智能批次、主数据、系统管理。
详细对象、角色、流程、页面和发布门槛见
[FT MES 精简标准版产品说明书](ft-mes-lean-standard-product-manual.md)。

### 3.2 标准版明确不做

- 不做 ERP 财务、采购、销售、人力和通用 OA。
- 不默认提供完整 EAM、完整 LIMS、完整 EHS 或全厂 EMS。
- 不把低代码平台的模型、视图、菜单和脚本设计器暴露为业务功能。
- 不为每种检验、记录或退料类型复制一套菜单。
- 不让 BPI 默认启动训练、数据湖和自动生产写回。
- 不让不同客户长期维护彼此分叉的核心代码。

### 4.2 BPI 增强

| 能力 | 决策 | 默认行为 | 发布条件 |
| --- | --- | --- | --- |
| 实时态势、候选、批次档案 | `KEEP_STANDARD` | `standard-bpi` 启用 | 真实生产上下文和点位作用域 |
| 点位、拓扑、规则、校准和运行开关 | `KEEP_STANDARD` | 管理员可见 | 职责分离、版本不可变和失败关闭 |

`standard-core` 不依赖 Kafka/Flink/MLflow 才能启动；`standard-bpi` 才启用 Kafka/Flink。

### 4.3 行业能力包

| 能力包 | 纳入能力 | 当前判断 | 重新启用门槛 |
| --- | --- | --- | --- |
| `pack-food-process` | 罐批、中间品、波美值/流量、CIP、果糖模板 | 优先建设 | 正式工艺/质量标准和物理点位验收 |
| `pack-equipment-reliability` | PATROL、设备巡检、缺陷移交、EAM/OEE | 部分可用 | 选定 EAM canonical 版本，修复空白页并闭合工单落库 |
| `pack-ehs` | WTS、JSA、作业票、安环巡检 | 动火有证据，其余不足 | 各票种状态机、审批、附件和签字逐项验收 |
| `pack-lab-compliance` | 样品全生命周期、留样、稳定性、资质、文档、电子签名 | 页面资产多、完成度不一 | 样品状态机、仪器/结果、审核和合规签字闭合 |
| `pack-energy` | 能源指标、计划、预测和分析 | 阻断 | 取得 Indicator 依赖并完成 PostgreSQL 迁移 |

### 4.4 内部控制台

以下能力不删除，但移出业务产品导航：

- 实体、模型、字段、视图、菜单、脚本和工作流设计器。
- 打印模板、Excel 模板和通用页面设计器。
- 微服务、Redis、接口开关、Nacos、任务和运行配置。
- license/软件狗兼容、门户主题和实施级个性化。
- 技术诊断、数据库映射和恢复补丁管理。

这些页面由单独域名或明确的“实施控制台”入口承载，只授予实施管理员。运行时配置页仍必须有后端授权，
不能靠隐藏菜单代替安全控制。

### 4.5 暂缓与退役

| 范围 | 决策 | 原因 |
| --- | --- | --- |
| 外部 ERP/WMS 高级仓储 | `HIDE_UNTIL_READY` | query-first、回执和补偿尚未完成现场联调 |
| WAPS/GIS 作业地图 | `HIDE_UNTIL_READY` | 缺 GIS 能力，已有页面返回 503 |
| WOM mobile | `HIDE_UNTIL_READY` | 版本不匹配且未部署验收 |
| 高级包装/自动立库 | `HIDE_UNTIL_READY` | 不属于首个流程制造标准闭环 |
| 多套历史通知渠道 | `RETIRE_AFTER_OBSERVATION` | 站内信/移动送达仍有失败，服务重复 |
| 同模块旧版本目录 | `RETIRE_AFTER_OBSERVATION` | 维护成本高，必须选 canonical 版本 |

## 5. 菜单合并方案

### 5.1 生产执行

原先的指令单、工序记录、指令记录、活动记录、检查记录、投料记录、产出记录、备料、配料、退料、
用料、报工和尾料，收敛为四个入口：

1. 制造指令。
2. 执行工作台。
3. 物料执行。
4. 报工与产出。

记录不再各自承担“新增”动作。写动作发生在制造指令或执行详情中，记录页只负责查询、详情和审计。

### 5.2 质量管理

来料、过程、成品、其他和质量巡检不再各复制“申请/报告/不合格/紧急放行/记录”。标准版固定四页：

1. 检验申请。
2. 检验报告。
3. 不合格处置。
4. 质量放行。

检验类型、来源、状态和批次作为筛选条件。完整样品生命周期只在实验室能力包显示。

### 5.3 配方管理

配方类型、工序类型、BOM、配方组态、标准配方、普通配方和图形化配方收敛为：

1. 配方中心。
2. 工艺路线。
3. 版本与发布。

普通、标准和图形化是配方类型或编辑模式，不是三个彼此独立的产品。

### 5.4 样品管理

实验室能力包保留五个生命周期组：登记与取样、收样与制备、结果录入与复核、审核与处置、台账与报告。
24 个原页面作为步骤或页签进入对应工作区，不再全部平铺为二级菜单。

## 6. 服务收敛目标

### 6.1 目标形态

标准版目标为 10 至 14 个应用部署单元、18 至 25 个总容器：

```text
edge-gateway
identity-access
platform-core
mes-master-data
mes-production
mes-quality
mes-inventory-trace
file-document
notification-worker
integration-hub
bpi-control        (standard-bpi)
bpi-stream         (standard-bpi)
industry-pack-*    (按需)
```

### 6.2 合并顺序

1. 先合并通知服务，保留一个可靠站内任务通道，外部渠道按需启用。
2. 再合并平台小服务到 `platform-core`，但 IAM、文件和网关保持独立安全边界。
3. 将 WOM 及其伴随入口收敛到 `mes-production`。
4. 将 material-wms 与 ProcessAnalysis 收敛到 `mes-inventory-trace`。
5. EAM、WTS、LIMS 和 EMS 移入行业 profile，标准版不常驻。
6. BPI 数据湖和模型 worker 改为任务型 sidecar，不常驻标准运行栈。

服务合并之前必须采集调用、topic、表、配置和文件依赖；菜单隐藏不等于服务可立即删除。

## 7. 分支与行业包策略

### 7.1 分支职责

| 分支 | 职责 | 生命周期 |
| --- | --- | --- |
| `main` | 标准核心、能力包契约、公共修复 | 始终可构建和部署 |
| `release/standard-x.y` | 冻结的标准产品版本 | 长期维护，接受受控补丁 |
| `industry/process-food` | 食品/生物流程包集成 | 发布前合入公共修复，不能复制核心 |
| `industry/equipment-reliability` | 巡检、EAM、OEE 集成 | 按行业版本维护 |
| `industry/ehs` | WTS/JSA/作业许可集成 | 按行业版本维护 |
| `industry/lab-compliance` | LIMS/样品/稳定性/资质集成 | 按行业版本维护 |

行业分支是版本集成边界，不是永久代码复制。行业实现放在独立 Maven 模块、前端 edition manifest、
Flyway location、Compose profile、权限种子和测试场景中。可复用修复必须先回 `main`。

### 7.2 客户差异

客户差异优先按以下顺序实现：

1. 主数据和工艺模板。
2. edition/feature manifest。
3. 规则、字典、表单和流程配置。
4. 独立行业扩展模块。
5. 最后才是短期客户分支，并要求明确回收日期。

禁止为每个客户复制 WOM、QCS 或主数据核心服务。

## 8. 安全下线流程

任何能力从“隐藏”进入“删除”必须完成：

1. 记录菜单、API、服务、topic、表、文件、任务和外部调用关系。
2. 生产或代表性试点环境连续观察至少一个发布周期。
3. 导出历史数据和配置，并完成恢复演练。
4. 先关闭新建入口，保留只读查询和审计。
5. 再移除路由和常驻服务，验证核心回归和回滚。
6. 最后在单独版本中清理源码、迁移模板和表，禁止顺手删除。

## 9. 三阶段执行计划

### 阶段 A：产品层隐藏与合并

- 建立 `standard-core` edition manifest。
- 菜单从现状收敛到八个一级入口。
- 隐藏 169 个空白旧页、技术控制台和未发布行业包。
- 不删除旧服务和表，保留一键回退。
- 建立六个标准端到端回归场景。

退出条件：标准角色只看到标准版能力；核心场景全通过；被隐藏页面无法通过普通业务权限访问。

### 阶段 B：核心体验与可靠性

- 合并 WOM 执行记录、QCS 检验类型、RM 配方入口和样品菜单。
- 补详情、空态、反向路径、幂等、重启恢复和错误 traceId。
- 完成文件服务性能治理和通知通道收敛。
- 为核心模块建立 API/事件契约测试和 PostgreSQL marker 回归。

退出条件：标准版可以独立实施，不要求用户进入低代码或数据库配置页完成日常业务。

### 阶段 C：服务与技术栈升级

- 选择每个业务域唯一 canonical 版本。
- 按目标部署单元逐个从 Java 8/Spring Boot 2 迁移到 Java 21 支持线。
- 合并服务、减小镜像和启动依赖，保留契约兼容层。
- 行业包独立发布和验收。

退出条件：标准版服务数量、资源、升级和恢复指标达到生产门槛；行业包可独立开关且不污染核心。

## 10. 当前立即决策

1. 以 `standard-core` 作为下一冻结版本，停止继续扩修全部菜单。
2. 将 BPI 分为生产运行能力和研发数据能力；前者进入 `standard-bpi`，后者默认关闭。
3. EAM、PATROL、WTS、完整 LIMS 和 EMS 转为行业包，不进入标准版完成度分母。
4. 先隐藏 169 个空白页面和全部业务无关技术控制台。
5. WOM、QCS、RM 和样品管理优先做菜单合并，不再为旧菜单逐个补按钮。
6. 选定 canonical 源码版本后再做 Java 21 和服务合并，避免升级 41 套历史目录。
7. 所有裁剪决策进入版本清单、Compose profile、权限种子和自动回归，不能只靠人工记忆。

## 11. 风险与防护

| 风险 | 可能后果 | 防护 |
| --- | --- | --- |
| 误删隐藏依赖 | 核心页面运行时报错 | 先隐藏、观测、解耦、最后删除 |
| 行业分支漂移 | 修复无法回流 | 公共契约在 main，行业代码独立模块 |
| 只改菜单不改授权 | 深链接仍可访问 | 后端 feature gate 与 RBAC 双门禁 |
| 历史证据过期 | 误判当前可用 | 每个冻结版本重跑浏览器/API/落库验收 |
| 一次性 Java 21 重写 | 长时间不可交付 | 按部署单元绞杀迁移，保持契约兼容 |
