# WOM 备料与配料标准产品取舍

更新时间：2026-08-03
适用范围：果糖连续生产线，默认数据库 PostgreSQL

## 结论

这组功能有修复价值，但不适合继续保留为 10 个彼此割裂的旧菜单。其业务价值集中在
“制造指令产生需求、仓储备料、称量配料、现场交接和异常补料”这一条链；标准产品应
收敛为 4 个工作台，角色差异通过待办、状态、数据权限和页签表达。

- 旧菜单整体与果糖业务匹配度约为 40% 至 50%。
- 收敛后的 4 个工作台与当前目标产品匹配度约为 75% 至 85%。
- 淀粉浆、水、糖液等连续大宗物料不应依赖人工“配料记录”；实际投入量应由 BPI 根据
  流量、阀路、泵状态、罐位和工序批次自动回写 WOM。
- 酶制剂、酸碱、活性炭、助剂等需要称量、复核和批次追溯的小料，继续使用配料执行。

## 功能取舍

| 旧入口 | 业务匹配度 | 标准产品处理 | 原因 |
|---|---|---|---|
| 补料备料 | 高 | 保留为“异常补料” | 处理少投、损耗、返工和临时追加，不进入正常主流程 |
| 备料需求 | 高 | 保留并升级为需求工作台 | 承接制造指令、配方、批次和计划数量 |
| 备料需求明细 | 中 | 合并到需求工作台明细页签 | 不需要独立导航，避免主从单据割裂 |
| 备料指令（调度员） | 中 | 合并到备料执行的调度视图 | 本质是同一指令的角色视图 |
| 备料指令（备料部门） | 高 | 合并到备料执行的作业视图 | 仓储拣料、确认、派送的主要入口 |
| 备料记录 | 中 | 合并为执行历史页签 | 记录应从指令详情进入，不单独形成工作入口 |
| 备料记录接收 | 中 | 合并为“待接收”状态 | 接收是状态动作，不应是独立产品模块 |
| 配料需求 | 高 | 保留在配料执行工作台 | 连接配方小料和工序活动 |
| 配料指令单 | 高 | 保留为配料执行主视图 | 支持称量、复核、完成和物料批次关联 |
| 配料记录 | 中 | 合并为配料历史页签 | 查询、追溯和异常处理使用 |

## 标准产品工作台

### 1. 备料需求

输入来自制造指令和配方，显示生产批次、工序、物料、需求量、需求时间和库存可用量。
允许动作：创建备料指令、调整、关闭。明细不再作为独立菜单。

### 2. 备料执行

合并调度员、备料部门、备料记录和接收页面。建议页签为“待调度、待备料、待派送、
待接收、已完成”。允许动作：备料、完成、停止、取消、提交、撤回、派送、接收。

### 3. 配料执行

合并配料需求、配料指令和配料记录。建议页签为“待下达、待称量、待复核、待投放、
已完成、退废”。允许动作：创建配料指令、批量配料、完成、撤回、派送、接收、配放、
退废。

### 4. 异常补料

只处理正常需求之外的补料。必须关联原制造指令、工序批次、原因、审批人和补料数量，
避免补料脱离物料平衡和批次谱系。

## 系统职责边界

| 系统 | 负责内容 | 不负责内容 |
|---|---|---|
| WOM/MES | 计划需求、指令、状态、人员动作、批次谱系和差异 | 高频原始测点长期存储 |
| BPI | 依据流量、泵、阀路、罐位和批次边界计算实际投入与工序归属 | 仓库库存账和人工审批 |
| WMS | 库存占用、拣料、出库、退库、批次和库位流水 | 工艺批次边界判定 |
| QCS | 原辅料、中间品和成品的检验、放行与不合格处置 | 备料调度和实际流量计算 |

## 未关闭门禁

“有效制造指令 -> 正常配料需求 -> 创建配料指令 -> 子项保存 -> PostgreSQL marker”仍为
`BLOCKED`，原因是测试环境当前只有两条不完整的退料测试需求，没有可安全使用的正常
生产配料需求。未完成这条真实写入前，不把配料业务链声明为已全部可用。

## 推进顺序

1. 先由标准制造指令生成一条正常生产配料需求，完成配料指令与子项真实落库验收。
2. 将 10 个旧入口在菜单上收敛为 4 个工作台，旧 URL 保留兼容跳转。
3. 接入 WMS 库存占用和批次出库，关闭计划量与实发量差异。
4. 对连续大宗物料接入 BPI 自动投入，人工配料只保留小料和异常补录。
5. 完成岗位权限、回滚、并发重复提交和断网重试验收后再进入标准产品分支。
